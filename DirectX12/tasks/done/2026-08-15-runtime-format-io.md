# Task (完了): 独自ランタイムモデルフォーマット(.mstc/.mskn/.mclp)の構造体+バイナリ読み書きユーティリティ

## 発端

ユーザーから「このプロジェクトには2つの目的がある: (1)DirectX12ゲームエンジン
開発 (2)ユーザー自身のゲームエンジンプログラマーとしての成長」という方針が
示され、`CLAUDE.md`に「Learning-first development」として明文化した。この方針の
最初の実践として、Action Timeline Editorの実装に入る前に「そもそもPMX/Xの2形式
アニメーション方式の違いが根本問題」という認識から、独自ランタイムモデル
フォーマットの設計・実装に着手した。

## 設計プロセス(対話形式、ユーザー主導)

Claudeが完成案を提示するのではなく、ユーザーに考えてもらい、Claudeがレビュー・
技術的な補足をする形で以下を段階的に決定した(詳細な理由は`DESIGN.md`「独自
ランタイムモデルフォーマット」節に記録済み):

1. Static(頂点+最低限のテクスチャ)/Skin(メッシュ+スケルトン+アニメーション)
   の2種類に分割 → Skinはさらに「メッシュ+スケルトン」と「アニメーション
   クリップ」を別ファイルに分離(PMX+VMD方式を踏襲、Action Timeline Editorの
   クリップ単位編集と相性が良いと判断)。
2. インポート時にPMX/Xから独自形式へ変換、エンジン内でオンデマンド+キャッシュ
   (別プロセスのツールは作らない)。
3. バイナリ形式、ヘッダーに全セクションの個数(=サイズ)を持たせ、ヘッダー読了後
   残り全部を1回のreadでバッファへ読み込み、メモリ上でスライスする方式
   (ユーザー発案)。
4. Index型はuint16(1メッシュ最大65536頂点、超過時は変換ツールがエラー)。
   ボーン名は固定長`char Name[64]`(超過時はエラー、切り詰めない)。
5. アニメーションは疎なキーフレーム+補間方式(1フレーム焼き込み方式は不採用)。
6. Staticの法線は持たせる。法線マップは「オブジェクト空間法線マップ」を採用
   (タンジェント空間と違い、頂点にタンジェントを持たせる必要がない。ただし
   変形しない剛体オブジェクト限定という制約があり、これがStatic/Skinの用途
   分割ともうまく整合することを確認した)。Skinの法線マップは今回スコープ外。

## 実装(Codexへ委任、2ラウンド)

1回目: `SourceCode/10_Ggraphic/RuntimeFormat/RuntimeFormat.h`(構造体定義)・
`RuntimeFormatIO.h/.cpp`(読み書きユーティリティ)を新規実装。オーバーフロー
安全な算術ヘルパー、頂点数上限チェック、ボーン名終端チェック、マジック
ナンバー/バージョン検証を含む。Codex環境ではスタンドアロン検証プログラムの
リンクができなかった(vswhere.exe不在)ため、実行確認は完了報告に含まれず。

2回目(フォローアップ): 1回目の成果物が`docs/coding-rules.md`の「member
functions, member variables — 1行コメント必須」規約を満たしていなかった
(ファイル先頭の`@brief`ブロックのみで、個々の構造体・メンバー・関数への
コメントが皆無)ことをClaudeが発見し、修正タスクとして投げ直した。あわせて
一部関数の「1文を`;`で連結して1行に詰め込む」書式を1文1行へ整形。ロジックは
一切変更していない。

## Claudeによる独立検証

Codex環境で完了できなかった往復テストを、Claude自身のPowerShell経由で
`vcvars64.bat`+`cl.exe`によるスタンドアロンビルドで実施(このプロジェクトの
既存の検証習慣「スタンドアロンcl.exe単体テスト」に倣った)。以下13項目全て
パス:
- `.mstc`/`.mskn`/`.mclp`それぞれの書き込み→読み込み往復でデータが一致
- 頂点数65537件でWrite関数が正しく`false`を返す(2形式)
- ボーン名がnull終端されていない場合にWriteMsknが`false`を返す
- マジックナンバーを破損させたファイルの読み込みが`false`を返す

2回目のコメント・書式修正後も同じ13項目を再実行し、ロジックが変わっていない
ことを確認済み(整形前後のファイルをバックアップと比較する形でも二重確認)。

本体プロジェクトのビルド(`scripts\build.ps1`)も各ラウンドでClaudeが独立して
実行し、0エラー0警告を確認済み。
